## Staging versus final qualification

Build apps with the ordinary `--profile power-repair` command. Each app archive
records the open/frozen cutoff selection. Full-image packaging rejects an open
selection by default. `--allow-open-selection` explicitly creates provisional
staging evidence; it neither closes the input list nor qualifies the final
cutoff result. Rebuild after the actual frozen source selection.

For the accepted origin, use `build_power_watch_candidate.py build` with
`--source-cohort accepted-1.0.7` and the exact accepted Runtime/native/System
checkouts. For the delivered origin add:

```sh
--source-cohort delivered-1.0.10 \
--source-bundle /path/to/preserved/power-candidate-bma423-final \
--installed-runtime /path/to/exact/runtime-0.1.53 \
--installed-native-dir /path/to/exact/runtime-0.1.53/dist/esp32s3-16mb-appdata-iq \
--installed-system-apps /path/to/exact/fcdb5b0a-system
```

Use separate output directories for the two origin proofs. If the target inputs
are identical, verify the final paired payload is byte-identical across both
routes. BMA456H has an initial-only image; no accepted preserving origin is
claimed for that sensor model.

## Update and data-loss implications

The private paired payload contains native firmware plus bootfs only. The
installed catalog check proves grammar, not availability: this file is not
reachable through the current updater catalog until separately approved
publication. No release or catalog change is authorized.

Every `FULL-INITIAL-ERASES-DATA` image is a separate destructive 16 MiB,
offset-zero operation. It erases NVS settings, credentials, Bluetooth bonds,
alarms, Points, app-data and both banks. Never substitute it for a preserving
update, and never raw-flash the paired payload at zero.

All proofs are offline. No target instructions, physical sleep/wake/current,
USB/device behavior, actual native flash/TLS/SPIFFS or default-app health
confirmation is qualified. No release, merge, catalog edit, flash or hardware
access is performed by this work.
